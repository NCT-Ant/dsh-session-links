# dsh-session-links

DeepSeek Harness 的「会话连接」插件。

Harness 自带「分岔会话」——把一个对话复制成两份。这个插件做的是相反的事：**把多个会话连接成一个协作小组**，让它们共享同一条用户消息、共享同一个工作目录，并且能互相派活、投票决策、通报进展。

> **下载安装**：打好的包在 [Releases](https://github.com/NCT-Ant/dsh-session-links/releases/latest) 里，文件名形如 `dsh-session-links-1.2.0.zip`（内含 `index.js`、`client.js`、`cordis.patch.yml`、`package.json`、`README.md`、`LICENSE`）。解压到一个目录后，在 Harness 的插件管理器里把**那个目录**当作本地 bundle 安装；装完按一次 `Ctrl+R` 刷新界面，标题栏才会出现「连接会话」按钮。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 连接会话 | 会话标题栏「连接会话」按钮 → 勾选 2 个以上会话 → 建成一组。支持**多个组同时存在**；一个会话同时只属于一个组，勾选即把该会话从旧组移出（互斥） |
| 群发消息 | 你发给组内任一会话的消息，会自动同步到组内其他会话，带来源标记 |
| 组内投票 | 会话自决策：`pick` 选出由谁执行 / `order` 排出多步任务的执行顺序，两轮投票 + 自动通知结果 |
| 小组长 | 可任命组内一个会话为组长，组长是**带权限的角色**：只有组长能用 `assign` 派活，组员拿到执行纪律 |
| 会话通报 | 向选定会话（或全组）发一条「只需知道、不必回复」的通知 |
| 会话颜色 | 侧边栏右键菜单给会话选低饱和底色，持久保存 |
| 上下文节能 | 紧凑转写、单条字符上限、重复消息跳过、静默执行（不必回复正文），并在面板里显示省下多少 |
| 连接标记 | 已连接会话在侧边栏显示链条图标，标题栏按钮显示 `已连接 · 组名 · 组长` |

## 安装

```bash
# 在 Harness 的插件管理器里，把本目录当作本地 bundle 安装
# 或在 profile 的 cordis.patch.yml 里 insert 一行：
- insert:
    - id: session-links
      name: dsh-session-links
```

安装后需要刷新一次 GUI（Electron 应用按 `Ctrl+R`）才能加载客户端部分。

## 使用

### 1. 建立连接组

1. 打开任意会话，点标题栏的 **连接会话**；
2. 点 **新建**（或直接勾选），勾选要连接的会话（至少两个），可填组名；
3. 点 **新建连接组**。

规则与细节：

- **勾选集就是该组的最终成员**：勾上的进去、取消勾选的移出，保存后生效；
- 一个会话只能属于一个组：勾选已在别的组的会话，它会从原组移出（面板会提前提示「会从「原组」移出」）；原组不足两人会自动解散；
- **点面板上方的「现有连接组」里任意一组**，即把该组成员载入到勾选区开始编辑，按钮变成 **保存该组成员**；
- **搜索框**可按标题或会话 id 过滤候选列表；
- 面板标题栏固定，只有内容区滚动，关闭按钮始终可见。

### 2. 组内投票（会话自决策）

在会话里直接交办任务即可，组内会走两轮：

- **第 1 轮**：每个成员各自给出计划大纲（`pick`）或顺序安排（`order`）；
- **第 2 轮**：把各家的提案互相可见，大家投票；
- **收尾**：按结果自动通知当选者/各步骤负责人开始执行。

也可以让会话显式调用：

```
session_links action=vote mode=pick  task="把 PDF 里的表格抽成 CSV"
session_links action=vote mode=order task="先做 A 插件，再做 B 脚本，最后出成品"
```

投票面向「快速决策」，不追求长篇推理；组内 2–4 个会话效果最好（开销约为成员数 × 2 轮对话）。

### 3. 任命小组长

面板里每个组员右侧有 **设为组长 / 撤销组长**。组长的职责是自动注入到它的系统提示里的：

1. 能派给组员的先派，不自己全包；
2. 用 `assign` 写明目标、验收标准、所需输入、交付物；
3. 用 `read` 跟踪进展、用 `announce` 同步关键决定；
4. 组员的产出由组长统一向用户汇报；
5. 不替组员做他们份内的事。

组员收到的是纪律：优先执行分派、完成后用 `send` 只回报「结论 + 产出路径」、不抢别人任务。`assign` 只有组长能调用，其他人调用会被拒绝并告知组长是谁。

### 4. 会话通报

面板「会话通报（不需要对方回复）」区块：选会话（或点「全选会话」）→ 写内容 → **通报给所选会话**。

适合「我装了某某插件，之后大家都能用」这类只需要知道的通知。收件方会以极短的一轮确认收到，不会展开干活。

### 5. 会话颜色

侧边栏会话行右键 → **会话颜色** → 12 种低饱和浅色或「清除颜色」。颜色存在本地数据文件里，重启后仍在。

### 6. 上下文节能

组内同步会占用每个成员的上下文，所以插件默认就开着三种省法，可在面板「上下文节能」里调：

- **紧凑转写**：前缀压成 `〔来源〕`，并提示「非你执行的任务就一句话确认」，抑制对方长篇回复；
- **单条上限**：默认 1200 字（200–8000 可调），超出保留头尾并提示用 `read` 取全文；
- **跳过重复**：8 秒内同源同内容只转一次；
- **静默执行**（默认开）：组内同步来的消息**不要求回复正文**——只有「任务失败/严重错误」和「用户在当前会话插话提问」两种情况才输出文字，其余处理完即可，有组长就把「结论 + 产出路径」用 `send` 报给组长，两行以内。这一条对内存和上下文的影响最大：组员不再长篇复述任务或贴代码。

面板底部实时显示：已转发条数、投递字数 / 原文字数、省下百分比、跳过条数。

## 会话可用的工具：`session_links`

| action | 参数 | 作用 |
| --- | --- | --- |
| `status` | — | 组成员、组长、节能用量 |
| `read` | `peerSessionId?`, `limit?` | 读某个组员最近的消息与工具调用 |
| `send` | `peerSessionId`, `text` | 给指定组员发一条消息 |
| `assign` | `peerSessionId`, `text` | **仅组长**：分派任务 |
| `vote` | `mode`(pick/order), `task`, `timeoutMs?` | 发起组内投票 |
| `announce` | `text`, `sessionIds?` | 向组内发通报（不必回复） |

## HTTP 接口（供脚本调用）

前缀 `/dsh-session-links`，均为同源请求：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/state` | 组、投票、颜色、节能配置与统计 |
| GET | `/sessions` | 可选会话列表 |
| GET | `/options` | 节能配置与统计 |
| POST | `/connect` | `{sessionIds, name?, groupId?}`（带 `groupId` 为编辑该组，`sessionIds` 即最终成员） |
| POST | `/disconnect` | `{sessionId}` |
| POST | `/dissolve` | `{groupId}` |
| POST | `/rename` | `{groupId, name}` |
| POST | `/leader` | `{groupId\|sessionId, leaderSessionId}` |
| POST | `/color` | `{sessionId, color}`（`#RRGGBB`，空值清除） |
| POST | `/options` | `{compact, maxChars, dedupeMs}` |
| POST | `/send` | `{sessionId, text, from?}` |
| POST | `/read` | `{sessionId, limit?}` |
| POST | `/vote` | `{groupId\|sessionId, task, mode, timeoutMs?}` |
| POST | `/announce` | `{text, sessionIds?\|groupId?}` |

## 数据与持久化

- 连接组、会话颜色、节能配置：`~/.dsh/session-links.json`（或 `$DSH_PROFILE_DIR/session-links.json`）
- 组内消息缓存、投票历史、节能统计：仅内存，插件重载后清空

## 已知限制

- 组员之间的消息走的是会话的 prompt 通道，因此对端仍会产生一轮（极短的）模型调用，不是零开销；
- **内存/磁盘开销随并行成员数近似线性增长**：每个成员都是一个完整的 agent 循环（独立上下文 + 独立工具进程），3 个成员同时跑时，系统内存与页面文件会明显上涨。建议 2–3 个一组、任务结束就解散组，并保持「静默执行」开启；
- 组员的回复不会自动回流给发件人，需要时用 `read` 拉取；
- 会话被删除/归档后会自动从组里剔除，成员不足两个的组自动解散，组长随之清空；
- 消息长度上限只影响「转发副本」，不会截断原会话里的内容。

## 开发

```
index.js   —— Host 半边：连接组状态、消息同步、投票、组长、HTTP 路由、工具
client.js  —— Client 半边：面板、侧边栏标记、右键菜单色板、样式注入
```

改完客户端代码要在 GUI 里 `Ctrl+R`，改完 Host 代码需要重载插件。
